- **Authored Workforce Packaging, Deploy Pipeline & Trigger Blueprint ([notes/managed-agents/deployment-and-triggers.md](../../notes/managed-agents/deployment-and-triggers.md))**:
  - Indexed in [notes/managed-agents/README.md](../../notes/managed-agents/README.md) alongside `playbook.md`.
  - Defined self-contained Git **Job Packages** (`agents/<job-name>/`: declarative `agent.yaml` with `environment`, `inline_mounts`, `dispatch`, and `triggers`, plus `SYSTEM.md`, `skills/`, `schema.json`, and `README.md`) reconciled via a 5-stage compiler/deploy pipeline (`simon deploy` / `simon agents sync` → inline `.agents/` bundle + SHA-256 digest → `/v1beta/credentials` → `/v1beta/agents` → `/v1beta/triggers` & `/v1beta/webhooks` → `deploy-lock.json`).
  - **Verified Upstream Gemini `v1beta` Control Plane Constraints**:
    - `/v1beta/agents` exposes `create`, `get`, `list`, and `delete` (up to 1,000 agents per GCP project) with **no in-place `update` or versioning yet** — requiring either **immutable SHA-8 blue/green IDs** (`prod-simon-<job>-<sha8>`) for zero-downtime rollouts or prefixed `delete` + `create` (`SIMON_AGENT_PREFIX=kevin-`) during dev (deleting an agent never disrupts running interactions or environments).
    - `agent_config.model` is **locked at `agents.create` time** (cannot be overridden per `interactions.create`, whereas `system_instruction`, `tools`, and `environment` can); verified models for `antigravity-preview-09-2026`: `gemini-3.8-flash` (default), `gemini-4-argon`, `gemini-3.6-flash`, and `gemini-3.5-flash-lite`.
    - Reserved ID prefixes (`antigravity-`, `gemini-`, `google-`, `youtube-`, `veo-`, `omni-`, `imagen-`, `lyria-`, `gemma-`) are forbidden; `simon-` and `<teammate>-simon-` remain collision-safe.
  - **Mapped All 3 Execution Trigger & Webhook Surfaces**:
    1. **Pattern A · Native Server-Side Cron Triggers (`client.triggers` / `POST /v1beta/triggers`)**: Zero-infra scheduled runs (`schedule`, `time_zone`, `max_consecutive_failures`, `execution_timeout_seconds`) that reuse a persistent sandbox `environment` across firings (e.g., `/workspace/seen_artists.json` for daily open-mic scouting) and bind `/v1beta/credentials` egress proxies.
    2. **Pattern B · Inbound HTTP Job API & External Webhooks (`POST /jobs/<job>`, `POST /webhooks/ingest/<source>`)**: Thin FastAPI / Cloud Run / Worker gateway that validates caller auth/HMAC, stages audio via `client.environments.files.upload(...)`, optionally runs sub-second Part 1 `gemini-decision-1` triage, and dispatches `client.interactions.create(background=True, webhook_config=...)` returning `202 Accepted`.
    3. **Pattern C · Outbound Gemini Event Webhooks for Zero-Polling Multi-Agent DAG Fan-In**: Combines per-request **Dynamic Webhooks** (`webhook_config` with `uris` + `user_metadata`, statelessly verified via Google's RS256 JWKS at `https://generativelanguage.googleapis.com/.well-known/jwks.json`) and project-wide **Static Webhooks** (`client.webhooks` / `POST /v1beta/webhooks`, verified via Standard Webhooks HMAC with 24h exponential-backoff retries) so parallel `performance-critic` + `booking-critic` completions hit a DB fan-in barrier and automatically launch `showcase-producer` → `pending_human_review`.
